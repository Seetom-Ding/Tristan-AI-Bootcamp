# Training Compute-Optimal Large Language Models（Chinchilla）— 论文分析

> Hoffmann et al., DeepMind, 2022。原文：[arXiv:2203.15556](https://arxiv.org/abs/2203.15556)。

## 先给结论

Chinchilla 重新估计了在固定训练计算预算下，语言模型参数量与训练 token 数应如何配比。论文训练了 400 多个 70M–16B 模型，结论是：**模型参数和训练 token 应大致同步增长；参数翻倍时，训练 token 也应近似翻倍。**

按照这个规律，70B Chinchilla 用约 1.4T token，在与 280B Gopher 相近的训练计算量下，显著超过 Gopher、GPT-3、Jurassic-1 和 Megatron-Turing NLG，并降低了未来微调与推理成本。

## 1. 研究问题与价值

GPT-3、Gopher 等模型常通过扩大参数量获得能力，却可能训练不足。固定训练计算量时，应该用更大的模型少量数据，还是更小模型更多数据？

价值在于：一次训练只能花有限预算，错误的参数—数据比例会浪费巨额计算；更小的 compute-optimal 模型还更便宜地部署和微调。

## 2. 之前研究与不足

Kaplan scaling laws 认为计算最优偏向大模型、较少 token。DeepMind 认为早期拟合的模型和数据范围不足，而且很多模型把数据量固定在较低水平，因此测出的最优比例可能偏斜。

GPT-3、Gopher 等大模型表现强，却没有充分看到数据；“更大”掩盖了欠训练问题。

## 3. 作者可能的思考路径

1. 在同一训练 FLOPs 下，较大模型每个 token 学得更有效，但可处理 token 更少。
2. 若模型训练得过少，验证损失仍会持续下降，说明预算应从参数转给数据。
3. 需要大量受控小模型扫描不同 \(N,D,C\)，而不是比较不同团队的成品模型。
4. 用拟合曲线预测一个未参与扫描的大模型，再与同计算量的旧模型公平比较。

## 4. 核心 intuition

大模型像容量更大的学生，但也必须有足够教材；如果 280B 模型只看少量 token，很多参数没有被有效训练。70B 模型看四倍数据，可以更充分地利用每个参数，最终质量更高且推理更便宜。

## 5. 方法与完整例子

假设训练预算固定：

1. 选择一组参数量从 70M 到 16B 的 decoder-only Transformer。
2. 对每个模型训练不同 token 数，记录验证 loss。
3. 拟合损失与参数量、token 数、训练 FLOPs 的联合关系。
4. 根据拟合预测 70B 模型的最佳 token 数。
5. 训练 70B Chinchilla 约 1.4T token，并用相同数量级计算与 Gopher 280B 比较。
6. 在 MMLU、GSM8K、问答、常识、代码等任务评估，并计算推理参数量。

## 6. 数学推导

### 计算近似

对 dense Transformer，训练 FLOPs 可近似为：

\[
C\approx 6ND,
\]

其中 \(N\) 是非 embedding 参数量，\(D\) 是训练 token 数。

### 联合损失模型

可用经验形式：

\[
L(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta}.
\]

固定 \(C=6ND\) 时，令 \(D=C/(6N)\)，得到只关于 \(N\) 的损失；对其求导，平衡参数误差和数据误差，就得到 compute-optimal 的 \(N,D\) 比例。论文从实验拟合 \(\alpha,\beta\)，而不是把它们当理论常数。

### 关键结论

最优参数量与 token 数近似同步增长：

\[
N_{opt}\propto C^{a},\qquad D_{opt}\propto C^{b},
\]

且在论文数据范围内 \(a\) 与 \(b\) 接近，直觉上就是“参数和数据一起加”。

## 7. 实验：问题 -> 设计 -> 答案

### 参数—token 比例

**问题**：早期大模型是否欠训练？  
**设计**：训练 400 多个模型，覆盖 70M–16B 参数和 5B–500B token。  
**答案**：给定训练计算，模型参数与训练 token 应近似同比增长；许多已有模型参数过大、token 太少。

### Chinchilla 是否真的超过大模型？

**问题**：更小模型多训练能否带来更好能力？  
**设计**：训练 70B Chinchilla，使用约 4 倍 Gopher 的数据、相近训练 FLOPs，比较多个下游任务。  
**答案**：Chinchilla 在广泛任务上显著超过 Gopher 280B，并达到 MMLU 67.5。

### 推理价值

**问题**：训练最优是否也更适合使用？  
**设计**：比较模型参数量、微调计算和推理成本。  
**答案**：70B 比 280B 更便于部署和微调；但这仍是参数量层面的估计，没有针对每种真实服务负载计算完整生命周期。

## 8. Takeaways

1. 大模型欠训练是一个预算分配问题，不只是容量问题。
2. 固定计算时，更多 token 能让较小模型达到甚至超过较大模型。
3. Chinchilla 为 LLaMA 的训练策略提供了直接依据。
4. compute-optimal 不等于 inference-optimal；实际请求量和输出长度还要单独建模。

## 9. 最脆弱的假设

论文假设实验拟合的缩放关系能外推到 70B 及更大模型，并且 token 质量在扩展时保持可比。若数据重复、污染或领域分布变化，最优比例会改变。

## 10. 一周最小复现

训练 5 个参数量 20M–200M 的 decoder-only 模型，每个模型配 3 个 token 预算；拟合固定 FLOPs 下的最优比例，再训练一个预测点之外的模型验证。记录 validation loss、一个小型下游任务和推理吞吐，验证参数—token 平衡，而非复现 70B。

## 11. 反例设计

构造一个参数容量主导的任务，例如每个样本含大量互不共享的随机事实，重复更多 token 只会重复训练信号。若固定 FLOPs 下更大模型始终胜出，说明 Chinchilla 的数据补偿结论依赖任务处于数据不足而非容量不足区域。

## 12. Follow-up idea

提出**双目标 scaling law**：同时拟合训练损失和服务期望成本，把请求量分布、输出长度、KV cache、批处理效率和更新频率加入优化。目标不是寻找唯一的 compute-optimal 点，而是给定应用生命周期输出一条 Pareto 前沿：训练多花多少，能换来多少长期推理节省和质量提升。
