一句话总结

T5 (Text-to-Text Transfer Transformer) 提出了一个统一的"文本到文本"框架，将所有 NLP 任务（翻译、摘要、问答、分类等）统一为"输入文本→输出文本"的格式。通过大规模的系统性实验（"预训练目标、架构、数据集、迁移策略"的全因子探索），T5 确定了最优配置——Encoder-Decoder 架构 + Span Corruption 预训练 + C4 数据集 + 多任务前缀微调——并在 11B 参数规模上实现了多基准 SOTA。这篇论文的价值不仅在于结果，更在于它为 NLP 迁移学习提供了一套系统性的"实证手册"。

1. 研究动机——NLP 需要一个统一的"操作系统"

1.1 2019 年 NLP 的碎片化现状

2019 年初，BERT 和 GPT-2 已经展示了预训练的巨大力量，但整个领域仍然面临一个结构性问题：每个任务都有自己专用的微调策略、输出格式和损失函数。BERT 用于分类时接一个 [CLS] + softmax 头；用于 SQuAD 时接 start/end span 预测头；用于 NER 时接 token 级分类头。GPT-2 通过零样本提示来适应不同任务，但性能不稳定。

Google 的 T5 团队问了一个更根本的问题：如果我们不认为这些任务是不同类型的问题，而统一视为"给定文本输入、生成文本输出"，会发生什么？

1.2 Text-to-Text 框架

T5 的核心思想是极简的：

  • 输入：任务前缀 + 原始输入文本。例如翻译："translate English to German: That is good."；摘要："summarize:
    "；分类："cola sentence: "
  • 输出：目标文本。翻译 → 德语文本；摘要 → 摘要文本；分类 → 标签文本 ("acceptable"/"not acceptable")
  • 所有任务共享同一损失函数：标准语言建模交叉熵（teacher forcing）

这意味着：模型的架构、损失函数、训练流程对于所有任务完全一致——唯一的差异是输入文本中嵌入的任务指令。

2. 系统性消融——NLP 迁移学习的"百科全书"

T5 论文最独特的贡献是一系列大规模的系统性消融实验——每个实验单独改变一个变量，保持其他条件不变。这是 NLP 领域第一次有人用如此系统的方法回答"什么样的预训练设置最好"。

2.1 架构选择：Encoder-Decoder > Decoder-Only > LM（论文 Section 3.2）

架构描述GLUE 均值
Encoder-Decoder完整 Transformer (12L enc + 12L dec)83.3
Language Model标准 causal LM（类似 GPT）80.2
Prefix LM输入部分双向、输出部分单向82.4

Encoder-Decoder 胜出的原因是：编码器的双向注意力天然适合理解输入文本，而解码器的因果注意力天然适合生成——两个子网络各自专业化的归纳偏置，比单一网络承担双重职责更有效。

2.2 预训练目标：Span Corruption 最优（论文 Section 3.3）

作者比较了多种无监督预训练目标：

预训练目标描述效果
Prefix LM给定前半段，预测后半段基准
BERT-style MLM随机 mask 15% token，逐 token 预测中等
Deshuffling将打乱的 token 恢复正确顺序略差
Span Corruption将连续的 token span 替换为唯一哨兵 token，让模型恢复被掩盖的 span最优

Span Corruption 的具体做法：将原文中的连续 token 片段（如"Thank you for inviting"）替换为哨兵 token <X> 和 <Y>，目标输出变为 <X> Thank you for inviting <Y> ...。与 BERT 的逐 token 预测不同，Span Corruption 要求模型预测整个连续片段——这更接近真实的文本生成场景。

数学形式上，设原始文本 $x$，被腐蚀的版本为 $x_{\text{corrupt}}$，目标为被移除的 span 序列 $y$，预训练损失为：

$$\mathcal{L} = -\sum \log P(y_i \mid x_{\text{corrupt}}, y_{2.3 数据集：C4 的构建

C4 (Colossal Clean Crawled Corpus) 是对 Common Crawl 的多阶段清洗产物：

  • 仅保留英文页面（langdetect）
  • 移除包含"脏话"关键词列表的页面
  • 移除包含 JavaScript 代码行的页面
  • 使用启发式规则去重（保留 3 句重复的页面被删除）
  • 移除包含"lorem ipsum"占位文本的页面
  • 最终规模：约 750GB 纯文本

实验显示，使用 C4 在所有下游任务上均优于使用 RealNews-like 数据集或未过滤的 Common Crawl。

4. 讨论与局限

局限 1——计算成本与可复现性：T5-11B 的预训练需要大量 TPU 算力。虽然已开源模型权重，但从头复现预训练的可行性有限。Google 团队发表了多篇后续工作（T5.1.1, UL2, Flan-T5）来修补和扩展 T5。

局限 2——Text-to-Text 不适合所有任务：对于结构化预测（如解析树、语义角色标注），强制输出为纯文本引入了不必要的序列化开销。将标签生成为文本在某些情况下不如分类头直接且准确。

独立判断——多任务前缀的脆弱性：T5 严重依赖恰当的任务前缀（"translate English to German:" vs "translate:" 可能给出不同的结果）。这种对提示格式的敏感性与 GPT-2/3 的提示工程问题一脉相承，说明我们尚未完全理解这些模型是如何"解析"任务指令的。

5. T5 的遗产

T5 是 NLP 工程化的巅峰之作——它不是靠一个令人惊讶的新想法取胜，而是靠对一个核心假设的系统性验证：所有 NLP 任务都可以统一为文本到文本的格式。这个假设后来被 GPT-3（few-shot 提示）和 ChatGPT（指令微调）进一步推向极致，但 T5 是第一个用大规模实证方式证明这条路线可行的关键节点。Google 后续的 Flan-T5、PaLM、Gemini 都直接继承了 T5 的 text-to-text 哲学。
