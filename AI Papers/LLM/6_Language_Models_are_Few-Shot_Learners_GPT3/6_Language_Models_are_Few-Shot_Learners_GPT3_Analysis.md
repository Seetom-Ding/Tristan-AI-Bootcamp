# Language Models are Few-Shot Learners（GPT-3）— 论文分析

> Brown et al., OpenAI, 2020。原文：[arXiv:2005.14165](https://arxiv.org/abs/2005.14165)。

## 先给结论

GPT-3 证明，把 GPT-2 继续扩大到 175B 参数后，模型可以在**不更新参数**的情况下，通过 prompt 中的自然语言说明和少量示例执行翻译、问答、分类、算术、代码和其他任务。这个能力称为 in-context learning（上下文学习）。

论文最重要的变化是接口：任务不再必须通过梯度微调写入参数，而可以临时写入上下文。它也清楚记录了能力不均衡、数据污染、幻觉、偏见、长文本不连贯和推理成本等限制。

## 1. 研究问题与价值

传统 NLP 需要为每个任务准备数千到数万标签并微调；人类往往看几个例子或一句说明就能学会新任务。GPT-3 问：规模足够大时，单一自回归语言模型是否能从上下文临时学习任务，而不做梯度更新？

价值是统一任务接口、降低小样本适配成本，并展示了“模型内知识 + prompt 中的任务定义”这一后来 LLM 产品的基本交互范式。

## 2. 之前方法与不足

- GPT-2 已显示 zero-shot 迁移，但规模和能力有限。
- BERT 等模型在下游任务上很强，却通常需要每项任务微调和任务头。
- 元学习和梯度式 few-shot 方法需要更新模型或额外训练循环。

GPT-3 的代价是巨大的训练和推理成本，并且上下文学习并不等价于可靠的符号推理或真正参数更新。

## 3. 作者可能的思考路径

1. GPT-2 表明，自然文本中存在任务格式，模型可能从 prompt 识别任务。
2. 如果能力随规模平滑增长，那么更大模型可能从 zero-shot 进化为 few-shot。
3. 使用同一个模型、同一个参数，在输入中放置不同示例，便可测试是否真正学会“任务条件化”。
4. 训练一个 175B dense Transformer，并在大量任务上统一比较 zero/one/few-shot，同时记录失败与污染。

## 4. 核心 intuition

Prompt 是一个临时的“程序说明 + 少量训练集”。模型不修改权重，而是在当前上下文中推断输入—输出映射。例如看到：`2+2=4`、`3+5=8`，再读到 `7+6=`，模型尝试续写 `13`。能力来自预训练权重中已有的模式，示例负责选择和格式化模式。

## 5. 方法与完整例子

任务：判断句子情感。

```text
Review: I loved this film.
Label: positive

Review: The plot was boring.
Label: negative

Review: The acting was excellent.
Label:
```

1. 175B decoder-only Transformer 接收整个 prompt。
2. self-attention 让最后位置读取前面示例中的输入和标签。
3. 模型估计下一个 token 的概率，生成 `positive`。
4. 没有反向传播、梯度和任务专用参数；换一组示例即可切换任务。
5. 论文以 zero-shot（只有任务说明）、one-shot（一个示例）、few-shot（多个示例）比较性能。

## 6. 数学推导

### 预训练

\[
\mathcal L_{LM}=-\sum_t\log p_\theta(x_t\mid x_{<t}).
\]

GPT-3 的任务能力来自同一个预训练分布，而不是下游更新。

### In-context 条件化

示例集合为 \(D_k=\{(x_i,y_i)\}_{i=1}^k\)，新输入为 \(x\)：

\[
\hat y=\arg\max_y p_\theta(y\mid D_k,x).
\]

随着 \(k\) 增大，模型可以根据上下文估计任务格式和映射；但这是隐式推断，不能保证等价于显式最小化任务损失。

### 规模趋势

论文观察到许多任务的 few-shot 性能随参数量提高，但也有任务近似随机或改善很小。平均趋势不代表每个任务都共享同一条缩放曲线。

## 7. 实验：问题 -> 设计 -> 答案

### 上下文学习是否有效？

**问题**：不微调能否完成新任务？  
**设计**：在翻译、问答、cloze、自然语言推理、算术、词语重排等任务上测试 0/1/few-shot。  
**答案**：GPT-3 在多个任务上达到强结果，部分任务接近或超过微调系统；但能力高度不均衡。

### 模型规模是否带来 few-shot 增益？

**问题**：in-context learning 是否只属于 175B？  
**设计**：比较 125M 到 175B 的八个模型。  
**答案**：多数任务随规模改善，175B 在 LAMBADA 等任务上获得显著提升；某些任务仍没有可靠改善。

### 生成文本是否逼真？

**问题**：大模型生成新闻是否接近人类？  
**设计**：给人类评审真实和模型生成的新闻，让其判断来源。  
**答案**：部分样本很难区分，但会重复、矛盾、跑题和产生事实错误。

### 污染和局限

**问题**：训练网页是否包含测试集？  
**设计**：扫描重叠并报告受污染数据集；分析干净子集。  
**答案**：若干数据集存在污染，作者承认评测解释受影响；GPT-3 还在常识物理、ANLI、WiC、长文连贯性上明显失败。

## 8. Takeaways

1. few-shot prompting 把模型使用从“训练参数”转成“构造上下文”。
2. 规模能提升上下文学习，但不能替代任务对齐、事实验证和工具使用。
3. 评测数据污染是网页预训练的核心方法学问题。
4. GPT-3 的成功来自规模、数据和通用接口的组合，不是单一算法技巧。

## 9. 最脆弱的假设

它假设 prompt 示例足以让模型识别任务，并且模型内已有相关知识。对新规则、长链推理、严格计算和没有自然语言示例的任务，in-context learning 可能只是模式匹配。

## 10. 一周最小复现

使用一个开源 100M–1B decoder 模型，在统一 prompt 模板下比较 zero/one/five-shot 的加法、情感和格式化抽取。控制示例数量、顺序和 token 长度，记录准确率、格式错误和重复采样方差；用一个小规模模型曲线验证“示例数与能力”的关系。

## 11. 反例设计

生成训练集完全不存在的新符号系统和随机映射，要求模型从 3 个示例推断 20 步规则。如果大模型输出流畅却无法超过随机，说明上下文学习依赖预训练中已有的归纳结构，并非普遍的快速学习。

## 12. Follow-up idea

提出**上下文学习的可验证编译器**：先让模型把 prompt 中的示例转换为显式的规则、程序或检索索引，再执行新输入，并用执行结果反向校验。研究问题是：把隐式上下文匹配转为可检查的中间表示，能否减少示例顺序敏感、算术错误和格式漂移，同时保留无需微调的灵活性？
