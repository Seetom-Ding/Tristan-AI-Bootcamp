一句话总结

GPT-3 将语言模型规模推至前所未有的 175B 参数，并证明了：一个足够大的自回归语言模型，在完全不进行梯度更新（冻结参数）的情况下，仅通过上下文中的 few-shot 示例（In-Context Learning），就能在大量 NLP 任务上达到有竞争力甚至 SOTA 的性能。这标志着从"预训练+微调"范式向"预训练+提示"范式的决定性转折。

1. 从 GPT-2 到 GPT-3——规模作为方法论

GPT-2 展示了零样本任务迁移的可能性，但性能与有监督方法差距仍然很大（翻译 5 BLEU vs SOTA 45 BLEU）。OpenAI 的核心假设是：这种差距主要来自规模不足，而非方法缺陷。 GPT-3 的逻辑线索是从 Scaling Laws 论文直接延伸的：$L(N) \propto N^{-0.076}$ 预测着从 1.5B 到 175B 的大幅性能增益。

GPT-3 的方法论与几乎所有之前的 NLP 论文根本不同：它不做微调。甚至不做梯度更新。所有"适应"发生在推理时——通过给模型喂几个带标签的示例作为上下文。这种范式被称为 In-Context Learning（上下文学习）。

2. 三种"不训练"的评估策略

策略上下文中的示例数描述
Zero-shot0仅任务描述 + 输入 → 直接输出
One-shot11 个示例 (输入→输出对) + 实际输入
Few-shot10-100K 个示例 + 实际输入 (K 受限于 2048 token 上下文)

这三种策略共享同一个冻结的模型——没有参数更新。模型从上下文示例中"学会"任务格式和预期输出模式，完全通过前向传播中的注意力机制实现。

3. 模型架构与训练

GPT-3 的架构与 GPT-2 几乎相同——Transformer Decoder，Pre-Norm，Sparse Attention 的变体（在深层使用局部+全局交错注意力模式以降低计算）。关键变化：

模型层数$d_{\text{model}}$头数$d_{\text{head}}$Batch Size学习率
GPT-3 175B9612288961283.2M token$6 \times 10^{-5}$
GPT-2 1.5B4816002564512$2.5 \times 10^{-4}$

训练数据组成（约 300B token）：Common Crawl（过滤后 410B token，训练时以 60% 权重采样）为最大来源。数据清洗使用了基于 GPT-2 的"质量分类器"来过滤低质量网页。

4.3 小样本下的"涌现"曲线

GPT-3 最引人注目的现象是：从 13B 到 175B，许多任务的 few-shot 性能出现非线性跃升。在 13B 以下的模型中，few-shot 性能缓慢增长；但在 175B 上，某些任务突然"开窍"——这在算术、翻译和常识推理任务上尤为明显。这是"涌现能力（Emergent Abilities）"概念的最早大规模实证之一。

5. 局限与争议

局限 1——推理成本：175B 参数的 GPT-3 每次前向推理需要约 350GB 显存（FP16），在 2020 年的硬件上部署几乎不现实。OpenAI 通过 API 提供服务而非发布模型权重的决定引发了开源社区的广泛讨论。

局限 2——上下文长度瓶颈：2048 token 的上下文限制意味着 few-shot 示例数量受到严格限制。对于需要大量背景知识的任务（如多文档 QA），这严重制约了 In-Context Learning 的效果。

局限 3——生成可靠性：GPT-3 在开放式生成中频繁产生事实错误、逻辑矛盾和"幻觉"。论文坦承模型"对世界的物理常识缺乏理解"。

局限 4——数据污染争议：训练数据源自 Common Crawl，部分测试集（如 LAMBADA、TriviaQA 的部分样本）可能被包含在训练数据中。虽然作者进行了去重和 n-gram 分析的缓解措施，但完全消除污染在 300B token 的语料上是不可行的。

6. GPT-3 的遗产——范式转换

GPT-3 是"预训练+微调"时代到"预训练+提示"时代的转折点。它用实证证明，足够大的语言模型可以作为一种"元学习器"——从上下文中的示例推断出任务需求，而不需要任何参数更新。这一发现直接催生了后续的 InstructGPT/ChatGPT（RLHF 对齐）、Codex（代码生成）和一系列"基础模型"研究。GPT-3 也是第一个引起公众广泛关注的 LLM——它不仅仅是 NLP 社区的研究对象，更成为了媒体报道和政策讨论的主题。
