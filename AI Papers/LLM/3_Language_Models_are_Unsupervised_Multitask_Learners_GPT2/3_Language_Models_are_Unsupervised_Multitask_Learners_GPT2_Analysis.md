# Language Models are Unsupervised Multitask Learners（GPT-2）— 论文分析

> Radford et al., OpenAI, 2019。原文：[arXiv:1902.06750](https://arxiv.org/abs/1902.06750)。

## 先给结论

GPT-2 的核心发现是：一个足够大的自回归语言模型，只用网页文本的下一个词预测目标，也会在没有任务标签和参数更新的情况下学习一些翻译、摘要、问答和阅读理解能力。论文没有声称 GPT-2 已经成为通用智能，而是证明了“语言建模目标 + 大规模多样文本 + 足够容量”可以产生零样本任务迁移。

## 1. 研究问题与价值

当时 NLP 主流流程是：为每个任务收集监督数据、设计输出头、微调模型。GPT-2 问：能否从自然存在的网页文本中学习任务，而不是为每项任务收集标签？

如果答案为是，任务定义可以从“训练一个分类器”转成“把问题和答案格式写进文本”，模型通过续写完成任务。这为 GPT-3 的 few-shot prompting 和今天的 instruction following 铺路。

## 2. 之前方法的不足

- 监督模型依赖大量任务特定标注，迁移到新任务成本高。
- 多任务训练通常需要显式任务标签和任务采样策略。
- 早期无监督语言模型规模较小，能生成文本但不稳定地执行任务。

GPT-2 的限制也来自同一目标：自回归续写并不保证理解问题、遵循格式或避免幻觉。

## 3. 作者可能的思考路径

1. 网页中自然包含问答、翻译、摘要和评论等“任务示例”。
2. 如果模型在足够多文本上学习续写，它可能隐式学习这些格式和对应关系。
3. 模型容量决定能否同时保存大量模式；扩大模型可能让零样本迁移出现。
4. 因此构建一个质量更高、去重更好的 WebText 数据集，训练多个规模的 GPT-2，直接用文本提示评估，而不做梯度更新。

## 4. 核心 intuition

监督任务的输入和标签本质上也是文本。例如把“中文句子 -> English translation”写成文档的一部分，语言模型只需继续文档。大模型从网页中学习“某种问题通常以什么形式出现、答案如何跟随”，于是任务被转换成了条件文本生成。

## 5. 方法与完整例子

输入：

```text
Translate English to French:
cheese
French:
```

1. 使用 WebText：从高质量 Reddit outbound links 收集约 800 万文档、约 40GB 文本，并做去重和过滤。
2. 用 byte-level BPE，把任意 Unicode 文本编码成 token，避免未知词表问题。
3. 训练 decoder-only Transformer，模型规模从 117M 到 1.5B。
4. 给定 prompt，模型对每个位置预测下一个 token，训练损失是交叉熵。
5. 推理时不更新参数，只输入任务说明和示例，让模型继续生成 `fromage` 等结果。

## 6. 数学推导

### 自回归目标

\[
\max_\theta \sum_{t=1}^{T}\log p_\theta(x_t\mid x_1,\ldots,x_{t-1}).
\]

模型没有任务 ID，也没有额外多任务损失；所有监督信号来自下一个 token。

### 零样本任务的条件概率

把任务描述和输入拼成 prompt \(c\)，模型选择输出 \(y\)：

\[
\hat y=\arg\max_y p_\theta(y\mid c).
\]

多选题可比较每个候选答案字符串的归一化 log-likelihood；生成任务则逐 token 采样或贪心解码。

### 规模与损失

论文观察到，模型容量增加时 WebText 验证损失和多个下游任务得分改善，近似呈 log-linear 趋势。这是经验关系，不是“任何任务都会随参数单调变好”的定理。

## 7. 实验：问题 -> 设计 -> 答案

### 零样本任务迁移

**问题**：无任务微调的语言模型能否执行 NLP 任务？  
**设计**：在 LAMBADA、Penn Treebank、WikiText-2、WebText 等语言建模任务，以及翻译、问答、阅读理解、摘要上用文本提示评测。  
**答案**：GPT-2 1.5B 在 8 个语言建模数据集中的 7 个达到当时 SOTA；在 CoQA 条件问答中达到 55 F1，接近或超过 4 个基线中的 3 个。

### 规模效应

**问题**：能力是否只是数据质量的结果？  
**设计**：比较 117M、345M、774M、1.5B 四个模型。  
**答案**：大模型在 zero-shot 任务上整体更好，说明容量对隐式任务学习重要。

### 文本生成质量

**问题**：模型能否生成连贯长文本？  
**设计**：人工检查新闻、故事和网页条件生成样本。  
**答案**：样本更连贯，但仍会重复、跑题和事实错误；生成质量的提升不等于可靠知识。

### 数据污染与限制

**问题**：WebText 是否包含测试集，导致分数虚高？  
**设计**：检查测试文本与训练数据的重叠，对部分数据集做污染分析。  
**答案**：作者承认若干数据集受到污染，尽量报告清洁子集；这显示网页规模带来的评测有效性问题。

## 8. Takeaways

1. 统一的语言建模目标可以产生跨任务能力，但能力并不稳定。
2. Prompt 是把任务格式写入上下文的接口，GPT-2 为后来的 in-context learning 提供了经验基础。
3. 数据质量、去重和污染检测与模型规模同样关键。
4. GPT-2 仍然是“续写器”，不是按人类意图可靠执行指令的助手。

## 9. 最脆弱的假设

论文假设网页中已经自然存在足够多的任务示例，且模型可以从文本格式中推断任务。对于低资源、结构化、需要真实世界工具或严格事实验证的任务，这个假设可能不成立。

## 10. 一周最小复现

用小型 Reddit/新闻语料训练 20M 和 100M 的 decoder-only Transformer。设计三个 prompt 任务：情感续写、格式化问答、简单翻译；不微调，只比较不同模型规模的 exact match、格式遵循和文本连贯性。再故意让训练集包含测试模板，观察污染如何改变分数。

## 11. 反例设计

构造一个训练文本中没有自然示例的新符号算法任务，例如随机生成的括号平衡规则，要求模型严格输出唯一结果。若模型生成流畅但准确率接近随机，说明“自然语言规模”不能替代任务监督和算法归纳偏置。

## 12. Follow-up idea

研究**任务格式可发现性**：给定同样的预训练模型，自动测量一个任务能否在自然文本中被“看见”。为任务构造不同 prompt 编码，学习一个任务表示，使模型先识别输入格式和输出协议，再生成答案。研究重点是区分“模型不会做”和“模型不知道你要什么”，并用污染控制的合成任务与真实任务分别验证。
