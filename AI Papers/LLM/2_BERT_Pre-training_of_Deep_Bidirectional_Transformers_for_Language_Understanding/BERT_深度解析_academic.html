一句话总结

BERT 通过掩码语言模型（MLM）和下一句预测（NSP）两个无监督预训练任务，首次实现了真正意义上的深度双向 Transformer 编码器预训练，在 11 项 NLP 任务上刷新了当时的 SOTA，并开创了 "预训练 + 微调" 的 NLP 范式。

1. 研究背景与动机

1.1 NLP 领域在解决什么问题？

2018 年之前的 NLP 系统面临一个核心矛盾：标注数据稀缺，无标注文本泛滥。对于大多数下游任务（文本分类、命名实体识别、问答等），获取高质量标注数据的成本极高，而互联网上每天产生数以亿计的无标注文本。

语言模型预训练（Language Model Pre-training）应运而生——先在大量无标注文本上预训练一个通用语言表示模型，再将它迁移到下游任务。这条路线在 2018 年初已经有了两个代表性的工作：

1.2 已有方法及其局限

ELMo（Peters et al., 2018）——基于特征的迁移学习。ELMo 分别训练一个从左到右和一个从右到左的 LSTM 语言模型，然后在每个下游任务中，将两个方向的隐状态拼接后作为额外特征注入任务模型。ELMo 的核心问题在于：① 两个方向的 LSTM 是独立训练的，并非真正的双向上下文建模；② 作为"特征注入"而非端到端微调，下游任务架构仍需大量定制设计。

OpenAI GPT（Radford et al., 2018）——基于微调的迁移学习。GPT 使用 Transformer Decoder 作为骨架，用标准的从左到右的语言模型进行预训练，然后将整个模型在下游任务上微调。GPT 在 GLUE 上达到了当时的 SOTA (75.1)。但 GPT 的致命局限在于：单向性。每个 token 只能看到它之前的 token，这意味着像 "银行" 这样的多义词无法利用右侧上下文（"去银行取钱" vs "河银行走"）来消歧。

简言之，2018 年的格局是：特征方法不够深（ELMo），微调方法不够双向（GPT）。BERT 的出发点正是填上这个坑。

2. 预备知识

2.1 Transformer Encoder 核心概念

BERT 完全基于 Transformer Encoder（Vaswani et al., 2017）。理解 BERT 只需复习两个概念：

自注意力（Self-Attention）：对于长度为 $L$ 的输入序列，每个 token 的 Query 向量与所有 $L$ 个 token 的 Key 向量计算点积 → softmax → 得到 $L$ 个注意力权重 → 用这些权重加权 Value 向量。公式为：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

其中 $d_k$ 是每个 attention head 的维度。这个公式的含义是：每个位置都从整个序列中"提取"相关信息，依注意力权重聚合。

多头注意力（Multi-Head Attention）：多个独立的自注意力头并行运算，各自学到不同层面的关系（如语法关系、语义关系、共指关系），最后拼接结果。BERTBASE 有 12 个头，BERTLARGE 有 16 个头。

2.2 为什么"双向"比"单向"难？

标准语言模型的训练目标是给定前文预测下一个词：$P(w_i \mid w_1, \ldots, w_{i-1})$。如果改成双向——同时用左右文预测中间词 $P(w_i \mid w_1, \ldots, w_{i-1}, w_{i+1}, \ldots, w_L)$——会出现一个 trivial 的解：每个词通过多层网络"间接看到自己"。这不是真正的预测，而是身份映射。BERT 的解决思路源自一个经典的心理学任务：完形填空（Cloze Task）。把目标词遮住，让模型根据上下文猜测它是什么——这就是 Masked Language Model（MLM）的直觉来源。

3. 方法详解

3.1 整体架构

BERT 的架构选择简单而精准：多层双向 Transformer Encoder 堆叠。与 GPT 使用的 Transformer Decoder 相比，BERT 的 Encoder 在每个自注意力层中允许每个 token 关注所有位置的 token——前、后、以及自身。这就是"深度双向"的工程实现。

设层数为 $L$，隐层维度为 $H$，自注意力头数为 $A$，前馈网络维度为 $4H$（论文 Table 1, Figure 1）：

模型层数 L隐层维度 H注意力头数 A参数量

BERTLARGE24102416340M
OpenAI GPT（对比）1276812110M

▲ 表1: BERT 两种规格与 GPT 的对比。BERTBASE 参数量与 GPT 完全相同，差异仅来自双向自注意力机制。

3.2 输入表示

BERT 的输入表示是三类嵌入的逐元素求和（论文 Figure 2）：

$$E_{\text{input}} = E_{\text{token}} + E_{\text{segment}} + E_{\text{position}}$$

详细解释：

  • Token Embedding $E_{\text{token}}$：使用 WordPiece 分词（词汇量 30,000）。每个序列的首 token 永远是特殊符号 [CLS]——其最终隐状态被用作聚合的序列表示。两个句子之间插入 [SEP] 分隔。
  • Segment Embedding $E_{\text{segment}}$：一个可学习的二分类嵌入，标记每个 token 属于句子 A 还是句子 B。这使得 BERT 原生支持句子对任务（如自然语言推理、问答）。
  • Position Embedding $E_{\text{position}}$：可学习的位置嵌入（非正弦函数），最大支持 512 个 token。

在源码中，输入嵌入的构建精确对应这段逻辑：

# modeling.py:184-193 — embedding_postprocessor
output = input_tensor                      # Token Embedding (WordPiece)
if use_token_type:
    output += token_type_embeddings        # + Segment Embedding
if use_position_embeddings:
    output += position_embeddings          # + Position Embedding
output = layer_norm_and_dropout(output)   # LayerNorm + Dropout

3.3 预训练任务一：Masked Language Model (MLM)

这是 BERT 最核心的创新。MLM 随机遮盖输入序列中 15% 的 token，让模型根据上下文预测被遮盖的原始词。具体遮盖策略（80-10-10 规则，论文 Section 3.1）：

概率操作原因
80%替换为 [MASK] token让模型学会 "看到遮盖就预测"
10%替换为随机词防止模型过分依赖 [MASK] token 的存在，迫使它检查每个位置的上下文
10%保持原词不变让模型不完全忽略非遮盖位置（微调时没有 [MASK]）

▲ 表2: MLM 的 80-10-10 遮盖策略。核心目的是弥合预训练（有 [MASK]）和微调（无 [MASK]）之间的分布差异。

这个设计在源码中的实现非常直白：

# create_pretraining_data.py:392-401 — create_masked_lm_predictions
if rng.random() < 0.8:
    masked_token = "[MASK]"            # 80%: mask
else:
    if rng.random() < 0.5:
        masked_token = tokens[index]   # 10%: keep original
    else:
        masked_token = vocab_words[    # 10%: random replacement
            rng.randint(0, len(vocab_words) - 1)]

MLM 的损失函数是标准的交叉熵，仅在被遮盖的 15% token 上计算。这个设计引入了一个训练效率问题：每个 batch 只有 15% 的 token 参与梯度更新，相比之下标准 LM 是 100%。MLM 收敛约比 LTR 模型慢，但最终精度绝对碾压——作者在 Appendix C.1 的实验证实，即便在 1M 步时 MLM 的绝对精度已远超 LTR 模型。

3.4 预训练任务二：Next Sentence Prediction (NSP)

许多关键的下游任务需要理解两个句子之间的关系——比如自然语言推理（前提和假设）、问答（问题和段落）。标准语言模型只建模句子内部的关系，不建模句子间的关系。NSP 的目标是让模型学会判断两个句子是否是原文中的连续句。

构造训练数据的方法：对于每个训练样本，50% 的时间 B 是 A 的真实后续句（标签 = IsNext），50% 的时间 B 是随机选取的句子（标签 = NotNext）。最终的 NSP 分类使用 [CLS] token 的最终隐状态 $C$，通过一个线性分类器预测二分类标签。损失函数为：

$$\mathcal{L}_{\text{NSP}} = -\log P(\text{IsNext} \mid C)$$

总预训练损失为两个任务损失之和（论文 Section 3.1）：

$$\mathcal{L} = \mathcal{L}_{\text{MLM}} + \mathcal{L}_{\text{NSP}}$$

3.5 微调：一个架构适配所有任务

BERT 设计上的优雅之处在于，微调时不需要修改模型架构。对于不同的下游任务，只需交换输入/输出格式（论文 Figure 4）：

▲ 表3: BERT 统一架构下的四种下游任务适配模式。

以 SQuAD 为例，回答抽取由两个可学习向量 $S \in \mathbb{R}^H$ 和 $E \in \mathbb{R}^H$ 实现。对于每个 token $i$ 的最终隐状态 $T_i$，start 概率为：

$$P_i^{\text{start}} = \frac{e^{S \cdot T_i}}{\sum_j e^{S \cdot T_j}}$$

end 概率同理。一个 span $(i, j)$ 的得分就是 $S \cdot T_i + E \cdot T_j$，选择分数最高且 $j \geq i$ 的 span 作为答案。源码实现如下：

# run_squad.py:580-587 — create_model
logits = tf.reshape(logits, [batch_size, seq_length, 2])
logits = tf.transpose(logits, [2, 0, 1])
unstacked_logits = tf.unstack(logits, axis=0)
(start_logits, end_logits) = (unstacked_logits[0], unstacked_logits[1])

# run_squad.py:657-660 — model_fn (loss computation)
start_loss = compute_loss(start_logits, start_positions)
end_loss = compute_loss(end_logits, end_positions)
total_loss = (start_loss + end_loss) / 2.0

这里有一个值得注意的工程细节：输入序列长度上限是 384（而非预训练的 512），stride 为 128，这是因为 SQuAD 段落可能极长，通过滑动窗口处理长文。

解读几个关键点：

  • CoLA（语言可接受性判断）：GPT 在此项仅 45.4（勉强超过随机），BERTLARGE 达 60.5。这说明双向上下文对语法判断至关重要——很多语法错误需要在 整个句子 范围判断一致性，单向模型天然受限。
  • RTE（文本蕴含识别）：GPT 56.0 → BERTLARGE 70.1，提升 14.1 个百分点。蕴含关系需要精确理解两个句子间的逻辑方向，单向模型会在判断 "(因)→(果)" 还是 "(果)→(因)" 时混淆。
  • BERTBASE vs GPT：两者参数量完全相同（110M），数据集不同（BERT 额外用了 Wikipedia）。但如后文消融实验所示，数据集差异只能解释一小部分提升——架构差异（双向 vs 单向）才是主因。

SQuAD 2.0 引入了"无法回答"的问题，这对模型提出了新的挑战：不仅要知道答案在哪，还要判断有没有答案。BERT 使用 $s_{\text{null}} = S \cdot C + E \cdot C$（[CLS] token 的 start/end 得分之和）作为"无答案"得分，与最佳非空 span 得分比较，通过阈值 $\tau$ 决策（在验证集上调参以最大化 F1）。

4.3 SWAG 常识推理

SWAG 是一个接地常识推理任务——给定一个场景描述，从四个备选延续句中选出最合理的一个。BERTLARGE 达到 Test 86.3%，比 ESIM+ELMo 的 59.2% 高出 27.1 个百分点，比 GPT 的 78.0% 高出 8.3 个百分点。这个巨大的提升暗示：双向上下文建模对常识推理有本质性的帮助——理解一个场景的延续需要同时把握"前面发生了什么"和"可能发生什么"。

几个值得注意的解读：

  • NSP 的贡献：去掉 NSP 后，QNLI 从 88.4 降到 84.9（-3.5）。QNLI 是自然语言推理任务，天然需要句子间的关系建模。相比之下，SST-2（单句情感分类）几乎不受影响（92.7 vs 92.6），验证了 NSP 设计目标与其实际效果的高度一致。
  • LTR + BiLSTM 不能替代 MLM：即便给 LTR 模型加上 BiLSTM（试图在顶层补偿双向性），SQuAD F1 也只能恢复到 84.9，仍远低于 MLM 的 88.5。这说明浅层双向是不够的，深度双向才是关键。
  • 结论：双向深度预训练是 BERT 超越 GPT 的根本原因。

5.3 特征方法 vs 微调方法（论文 Table 7）

在 CoNLL-2003 NER 任务上，作者比较了两种使用 BERT 的方式：

  • 微调 BERT：BERTLARGE 达到 Test F1 92.8
  • 特征提取（concat 最后 4 层隐状态 + BiLSTM）：Dev F1 96.1，仅比微调低 0.5

这表明 BERT 既适用于微调范式，也适用于特征注入范式——给那些不想修改整个模型架构的场景提供了灵活的选择。

6. 讨论——这个工作的意义和边界

6.1 适用边界

BERT 的设计隐含了几个前提假设：① 任务可以被建模为"输入序列 → 标签/span"的映射；② 输入长度 ≤ 512 token。对于生成任务（如翻译、摘要），BERT 的 Encoder-only 架构并不直接适用——尽管后来的工作（如 BART, T5）通过 Encoder-Decoder 架构弥补了这一空缺。

6.2 未解决的问题

预训练-微调之间的分布差异：MLM 的 80-10-10 策略是权宜之策，而非根本性的解决方案。[MASK] token 在预训练中出现频率为 15% × 80% = 12%，但在微调中为 0%。后续工作（如 XLNet 的 Permutation LM, RoBERTa 的动态 masking）分别从不同角度应对这个问题。

计算成本：预训练 BERT 需要 4 天 × 16 Cloud TPU。这个成本使得大多数研究者无法从头复现 BERT 预训练——他们只能使用 Google 发布的预训练权重。这也引发了 NLP 领域关于可复现性和计算公平性的广泛讨论。

序列长度限制：512 token 的上限对于长文档理解任务（如文档级问答、长文本摘要）是不足的。Transformer 自注意力的 $O(n^2)$ 复杂度意味着直接扩展序列长度代价高昂。

7. 局限分析

作者自述的局限：论文 Appendix C.1 明确指出 MLM 模型收敛速度比 LTR 模型慢——"MLM 在每步中只从 15% 的 token 中学习，而 LTR 从所有 token 中学习。"虽然作者随后强调"MLM 的绝对精度远超 LTR"，但收敛速度确实意味着在固定计算预算下的次优性。

作者自述的局限 2：论文 Section 5.1 的消融实验显示 NSP 对某些任务几乎没有帮助（如 SST-2 仅降 0.1 分）。后续工作 RoBERTa（Liu et al., 2019）进一步发现去掉 NSP 在某些配置下甚至略有提升，说明 NSP 的设计是"对的任务、对的直觉，但不是最优的实现"。

独立判断——数据泄漏风险：BERT 的预训练数据包含英文维基百科，而许多下游任务（如 QNLI 源自维基百科）的训练/测试集也可能包含维基百科文本。尽管概率很低，预训练期间对下游任务数据的间接接触可能轻微抬高了评测结果。

独立判断——推理效率：340M 参数的 BERTLARGE 在线推理延迟在 2018 年的硬件上是一个实际瓶颈。后续大量工作（DistilBERT, TinyBERT, MobileBERT, ALBERT）专门致力于缩小 BERT 的推理体积，侧面印证了部署层面的困难。

8. 结论——BERT 留下的遗产

BERT 的核心贡献可以凝练为三条：

  1. 证明了深度双向预训练的优越性：MLM 比单向 LM 更有效地利用了文本中的上下文信息，这种优势在需要精细语义理解的任务（如 RTE +14.1%、MRPC +9.2%）上尤为突出。
  2. 建立了"预训练-微调"的统一范式：一个预训练模型 + 最小化任务适配层 → 覆盖 11 类不同任务。这种简洁性极大地降低了 NLP 系统的开发门槛。
  3. 开创了 NLP 的规模化时代：论文将参数规模从 100M 推到 340M 并证明了规模收益。这直接启发了后续的 GPT-2/3、T5、Megatron-LM 等更大规模的预训练探索。

截至 2026 年，BERT 已被引用超过 70,000 次。它的直接技术贡献（MLM、输入表示设计）已经被许多更新的架构所超越，但它建立的"预训练 + 微调"范式至今仍是 NLP 产业应用的主流路线。从这个意义上说，BERT 不仅仅是 2018 年的一篇好论文——它定义了 NLP 在深度学习时代的工作方式。
